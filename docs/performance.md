# 性能分析与优化建议

> 针对《工厂原型 Factory Proto》的性能审查报告。项目为纯 Canvas + 原生 JS 的
> 《异星工厂》式游戏，性能瓶颈随工厂数量增长集中在三处：
> **每帧模拟（update）、每帧渲染（render）、UI/统计刷新**。
> 本文先盘点已有优化，再记录本轮新实施的优化，最后给出后续可做的方向。

## 二、本轮新实施的优化

### 1. 传送带/分流器排序改为近似有序插入排序（P1，热路径）

- **问题**：`Belt.update`/`Splitter.update` 每帧对带上物品做全量
  `Array#sort`。传送带是数量最多的实体；而物品每帧只前移、新物品从尾部
  进入，数组几乎总是有序的，`sort` 的 O(n log n) 与比较器开销纯属浪费。
- **方案**：`sortItemsDesc` 插入排序——对近乎有序的数组只需 O(n) 次比较、
  零交换、零分配。极速带（ExpressBelt 继承 Belt）自动受益。
- **位置**：devices/belt.js、devices/splitter.js

### 2. 地下带配对关系按网格版本号缓存（P1，热路径）

- **问题**：`findMate`/`findBackMate` 要沿朝向扫描至多 maxDist 格
  （普通 6/快速 14/极速 20）。配对状态被 update（每帧）、
  `DEVICE_STATUS`（每个可见地下带每帧）、`drawUnderground`
  （isEntrance+isExit，即每帧两次）反复查询：一条可见的未配对极速地下带
  一帧最多触发上百次 `entAt`。
- **方案**：新增全局单调递增网格版本号（任何 `addEnt`/`removeEnt` 自增），
  配对结果缓存在实体上并记录版本号，访问时版本不一致才重算。
  建造/拆除是低频事件，缓存命中率为帧级 100%，且不存在漏失效。
- **位置**：core/entity.js（`gridVersion`）、devices/underground.js（`pairInfo`）

### 3. 组装机流体配方缓存 + portFlow 快速路径（P1）

- **问题**：三类组装机每帧调用 `portFlow()` → `fluidRecipe()`
  每次都做两轮 `Object.keys().filter()` 分配；随后 `forEachNeighborEnt`
  再分配一个 Set——即使这台组装机根本没有流体配方（绝大多数情况）。
- **方案**：fluidRecipe 结果只随 recipe 变化，按配方 id 惰性缓存；
  portFlow 增加"输入不缺且无待输出"快速返回，跳过邻居扫描。
- **位置**：devices/assembler.js（AssemblerMK2/3 继承生效）

### 4. 矿点烘焙进地形分块缓存（P1，渲染热路径）

- **问题**：地形底色虽有离屏缓存，但矿点此前每帧在视口内逐格实时重绘：
  每格 `getOreType`/`getOreAmt`（字符串 key 拼 Map）+ `hash2`
  （两次 `Math.sin`）+ 矿点圆弧路径。放大视野（z=2.2）时视口可达约
  5000 格/帧。
- **方案**：矿点直接画进 chunk 离屏画布；开采消耗时由 `consumeOre`
  给所在 chunk 标脏，下次取用该 chunk 时原地重绘一次（同帧多次消耗只重绘
  一次）。读档/导入时清空缓存防止陈旧矿量。统计页新增"脏重绘"计数。
- **位置**：render.js、world.js（consumeOre 标脏）、main.js（读档清缓存）

### 5. Alt 悬停提示不再全量扫描实体（P1）

- **问题**：按住 Alt 显示详情时，每次 mousemove 的 `mapTipAt` 遍历全部
  `G.ents` 找流体口图标，大工厂下悬停明显卡顿。
- **方案**：流体口图标恒画在设备脚印内部格上（fluidIconCell），因此鼠标
  所在格命中的设备就是图标所属设备——直接 `entAt(tx,ty)` 即可，O(1)。
- **位置**：ui.js

### 6. 统计速率单遍快照 + 事件队列头游标（P2）

- **问题**：统计面板每个物品的速率各扫一遍事件队列，O(物品×事件)
  （上限 4096×N）；`trackProd` 用 `shift()` 剪枝，整体 O(n²)。
- **方案**：一次遍历聚合出 `item -> {gain, loss}` 快照并按签名缓存；
  队列头部改游标推进、过半时一次性压缩。
- **位置**：stats.js

### 7. 渲染桶遍历复用缓冲（P2）

- 每帧的桶 key 数组与去重 Set 改为模块级复用，消除每帧固定分配带来的
  GC 压力。位置：core/entity.js、render.js

### 8. 其他小项

- 快捷栏槽位/计数元素引用缓存：`refreshHotbar` 由每次物品增减触发，
  不再每次做 10×2 次 DOM 查询（ui.js）。
- **修复 bug**：drill.js `drillPanelLive` 引用了未定义的 `body`
  （ReferenceError）。该异常会被主循环 try/catch 吞掉，导致打开采矿机/
  电钻/抽油机面板期间统计与性能面板停止刷新——直接影响性能观测工具本身。
  已改为 `document.getElementById('mach-rate-block')`。
- index.html 中被修改脚本的 `?v=` 版本号已同步递增。

### 验证方式

Node 最小 DOM 桩加载全部脚本跑冒烟测试：23 项断言全过（乱序插入后排序恢复、
地下带配对随增删正确失效/恢复、配方缓存跟随、矿点标脏→重绘→清脏、速率快照
数值、桶遍历复用不串场）；另跑了 1200 帧"采矿机→传送带→地下带对→分流器→
机械臂→箱子"端到端流水线 + 渲染路径压测，无异常、物流正常送达。

## 三、后续优化建议（未实施，按性价比排序）

1. **模拟距离分级（active zone，异星工厂核心思想）**
   目前主循环仍更新全量 `G.ents`。可按与玩家距离分级：近处全速更新，
   远处每 N 帧 tick 一次（或仅推进进度条不动动画）。大工厂下这是最大的
   收益来源，但会改变"离开后工厂是否继续运转"的游戏语义，需要产品决策
   （异星工厂的做法是按"已探索区块"保持活跃，可借鉴）。

2. **设备静态外观精灵化**
   传送带主体（含侧面接入条）、炉子/装配机外壳等静态部分预渲染成 sprite
   缓存（keyed by type/dir/朝向组合），每帧只 blit + 叠加动态部分
   （流动箭头、物品 dot、进度环）。传送带数量最大，收益显著；
   动画的相位可用全局时间取模在 blit 后补画。

3. **按类型分批绘制**
   当前逐实体切换 fillStyle/strokeStyle/lineWidth。可按
   `DEVICE_RENDER[type]` 分组遍历桶内容，减少 canvas 状态机切换次数；
   配合 2 效果更佳。

4. **电网分组**
   电网目前是全网单一 sat。设备多了以后可按连通性把发电/耗电拆成若干
   独立电网分别结算（异星工厂行为也更正确），updatePower 只重算拓扑变化
   或成员功率波动的组。

5. **炮塔目标搜索空间索引**
   炮塔每帧线性扫全部敌人 O(塔×敌)。敌人大规模出现时可复用桶索引或
   维护敌人网格。

6. **自动保存异步化**
   `JSON.stringify(serializeAll())` 在主线程一次性完成，大存档会掉帧。
   可分帧序列化或移入 Web Worker（配合 7）。

7. **模拟线程化（长期）**
   把确定性世界生成/解码、统计聚合、存档序列化移入 Web Worker；
   主线程只保留输入、模拟调度与渲染。

8. **杂项**
   - `hash2` 用 `Math.sin` 实现，烘焙矿点后每帧已无调用，若日后回到
     每帧路径可换成整数 hash（mulberry32 已有）。
   - 敌人/子弹数组每帧 `filter` 重建，量大时可改交换删除或对象池。
   - `powerSummary` 每次 spread 两个 Set 成新数组，仅在统计页打开时
     每 0.25s 执行一次，量级小，暂无必要。

## 四、如何持续观测

游戏内置了观测手段，调参时建议对照使用：

- 设置 → 性能优化：限制 DPR（默认开）/ 省电半分辨率模式；
- 统计面板 → 性能页：FPS、单帧耗时、实体数、地形缓存命中/脏重绘、
  LOD 分级状态；
- 开发者调试面板：时间/带速/机械倍率滑杆可用于放大负载复现瓶颈。
